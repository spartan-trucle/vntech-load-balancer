Algorithms

Two families:

  • Spread — send each request to whoever is next or least busy.
  • Hash — send the same key to the same backend every time.

3.2 · Least connections

Send to the backend with the fewest requests in flight right now

  • pod-b is stuck in a 2-second GC pause. Its requests pile up.
  • Round robin still gives it every third request, and each of those waits behind 41 others.
  • Least connections sees 41 vs. 0 and sends to pod-c. A slow backend gets fewer requests automatically, because it finishes fewer.
  • ALB calls it least_outstanding_requests; NGINX least_conn; HAProxy leastconn; Envoy LEAST_REQUEST.

3.3 · Power of two choices

Pick two backends at random, send to the less busy one

// Envoy LEAST_REQUEST does this by default (choice_count = 2)
fun pick(pods: List<Pod>): Pod {
  val a = pods.random()
  var b = pods.random()
  while (b == a) b = pods.random()
  return if (a.inFlight <= b.inFlight) a else b
}
  • Scanning all 200 pods for the minimum costs O(n) per request. Two random picks cost O(1).
  • It still avoids the worst pod: a stuck pod only wins when it is compared with a pod that is even worse.
  • It also fixes the herd: with several balancers, each only knows its own in-flight counts. Random pairs keep them from all choosing the same "idle" pod at once.
  • Result: close to least-connections quality, at round-robin cost. A good default for L7.

Hash on a user ID or cache key when locality matters: a per-user cache, a shard, a WebSocket room. NGINX hash $key consistent, HAProxy balance uri, Envoy RING_HASH / MAGLEV.

3.6 · Consistent hashing

Put nodes and keys on one ring. A key belongs to the next node clockwise.

  • Hash each node's name to a point on a ring of 232 positions. Hash each key the same way.
  • Walk clockwise from the key; the first node you meet owns it.
  • Add node D: only keys between C and D change owner, and they all move to D. Everything else stays put — about 1/N of the keys move.
  • With 3 points the arcs are uneven. Give each node 100–200 virtual nodes (A#0 … A#149) so every node owns about the same share.
